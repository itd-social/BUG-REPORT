# Как правильно оформить Issue

Чем точнее заполнен репорт — тем быстрее разработчик сможет его воспроизвести и исправить. Ниже — обязательные и желательные пункты.

## Перед созданием issue

- **Проверьте, нет ли уже такого репорта** (поиск по Issues, включая закрытые).
- Убедитесь, что проблема воспроизводится не только у вас (по возможности).
- Если баг связан с конкретным аккаунтом/данными — не публикуйте пароли, токены, персональные данные третьих лиц.

## Обязательные поля

### 1. Заголовок
Короткий и конкретный. 

- ❌ «Не работает»
- ✅ «При загрузке аватара PNG > 5MB страница профиля зависает»

### 2. Описание проблемы
Что именно происходит не так, своими словами.

### 3. Шаги для воспроизведения
Пронумерованный список, максимально подробно:

```
1. Открыть итд.com/@profile
2. Нажать "Создать пост и загрузить картинку"
3. Выбрать PNG файл размером 10MB
4. Нажать "Сохранить"
```

### 4. Ожидаемый результат
Что должно было произойти.

### 5. Фактический результат
Что произошло вместо этого. Текст ошибки — копировать точно, не пересказывать.

### 6. Окружение
- Устройство: desktop / mobile / tablet
- ОС: Windows / macOS / Android / iOS + версия
- Браузер и версия (или приложение)
- Разрешение экрана (если баг визуальный)
- Аккаунт/URL, где воспроизводится (если применимо)

## Желательные, но очень полезные

- **Скриншот или видео** — особенно для визуальных багов и UI-глюков.
- **Консоль браузера (F12 → Console/Network)** — скриншот ошибок красным текстом, если баг похож на технический.
- **Частота воспроизведения** — всегда / иногда / один раз.
- **Когда началось** — после конкретного обновления, всегда так было и тд.

## Что не нужно делать

- Не объединяйте несколько разных багов в одном issue — заводите отдельные.
- Не пишите «то же самое, что и в issue #12» без ссылки и подробностей — если баг похож, но детали другие, лучше отдельный репорт со ссылкой на связанный issue.
- Не используйте issue как чат поддержки — только структурированные факты о проблеме.

## После создания

- Разработчик может пометить issue `needs-info`, если данных не хватает — в этом случае, пожалуйста, дополните репорт как можно быстрее.
- Не удаляйте и не редактируйте исходные факты после ответа разработчика — дополняйте комментарием, чтобы сохранялась история.
